Semi-bandit weekly scheduling — book clients into experts' calendars while learning who fits whom

Every week you fill the experts' open slots with clients (one client per slot). You only learn how good a booking was once you actually make it. Four policies race to the best weekly schedule.

The charts and totals use hidden truth for evaluation only. Learners receive only the noisy outcomes listed in the feedback panel. Best-so-far means the best action visited, evaluated with hidden truth.

Columns = experts (header colour = specialty), rows = Mon–Fri × AM/PM. Grey cells = expert unavailable. A filled dot = a booked client, coloured by client type; brighter = the policy rates that booking higher. Click a legend entry to show that policy's week.

Booking quality is a hidden matrix factorization: every client has a latent "needs" vector and every expert a latent "strengths" vector, and quality is how well the two align (clients/experts are coloured by their latent direction, so matching colours should fit) plus a per-booking quirk, seen with noise only when the booking is made. Each week the optimizer solves the exact max-weight assignment of clients to open slots (the in-browser analogue of an LP in Pyomo/CVXPY) on each policy's current estimates. Availability removes most cells, so "just try every client in every slot" is expensive — which is exactly when structure pays: Contextual + per-pair learns a coarse client-group × expert-group compatibility table (a low-rank read of those latent factors — one good booking teaches it about every similar pairing) plus a per-booking correction, and pulls ahead of the tabular policies that must probe almost every client·slot pair. Toggle the Bipartite view to see clients linked to experts with their capacity. Greedy locks onto an early guess; random never learns.

Solver model · browser code + CVXPY equivalent

What runs here: Hungarian maximum-weight assignment in JavaScript. This finds an optimal assignment for the current score matrix; the scores are learned estimates.

Rows are clients; columns are available (expert, day, AM/PM) slots. Unavailable calendar cells never become columns. Each open slot can serve one client. The learner turns its estimates and uncertainty into objective coefficients. The solver chooses a feasible action. Only the selected components then return noisy feedback.

The optimization model · CVXPY

Python reference code, shown for reading and running locally. Install with pip install cvxpy highspy numpy. The browser Hungarian algorithm solves the same assignment objective without a Python runtime.

import cvxpy as cp
import numpy as np

def ucb_scores(sums, counts, t, beta, prior, scale, minimize=False):
    """Tabular policy: optimism lowers costs or raises rewards."""
    means = np.divide(sums, counts, out=np.full_like(sums, prior, dtype=float),
                      where=counts > 0)
    bonus = beta * scale * np.sqrt(np.log(t + 1) / (counts + 1))
    return np.maximum(0.02 * prior, means - bonus) if minimize else means + bonus

def solve_assignment(scores):
    """Rows = clients; columns = experts (matching) or OPEN slots (scheduling).

    Scheduling creates columns only for available (expert, day, time) slots.
    In these demos there are exactly as many clients as columns.
    """
    scores = np.asarray(scores, dtype=float)
    n, m = scores.shape
    if n != m:
        raise ValueError("These demos use a square, complete assignment")
    x = cp.Variable((n, m), boolean=True)
    constraints = [cp.sum(x, axis=1) == 1,  # each client gets one assignment
                   cp.sum(x, axis=0) == 1]  # each expert/open slot used once
    problem = cp.Problem(cp.Maximize(cp.sum(cp.multiply(scores, x))), constraints)
    problem.solve(solver=cp.HIGHS)
    if problem.status != cp.OPTIMAL:
        raise RuntimeError(f"Assignment solve: {problem.status}")
    return np.argmax(x.value, axis=1)

def update_selected(sums, counts, observations, undirected=False):
    """Each (i, j, value) is one selected component's noisy outcome.

    No samples for unchosen components. Contextual policies additionally
    update shared group estimates from these same observations.
    """
    for i, j, value in observations:
        sums[i, j] += value
        counts[i, j] += 1
        if undirected:
            sums[j, i] += value
            counts[j, i] += 1

For tabular UCB, call ucb_scores with the stored sums and counts, the current round, β, and prior=55, scale=30. Pass those scores to solve_assignment. Contextual policies replace these coefficients with shared-group predictions plus per-component corrections; the feasibility model stays the same. Random skips optimization.
