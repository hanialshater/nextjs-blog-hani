# Artifact before account

A reviewer who reads the builder's explanation first inherits the builder's reasons to approve. Five reviewers like
that count as one witness.

1. Start from the artifact itself: run it, open it, read its output. Use a walkthrough (transcript plus
   screenshots) if the company has one.
2. Write your first findings **before** opening the builder's notes, design or meta files.
3. Only then read the account, and add what it changes, marked as such.
4. Briefs to evaluators link the artifact, never the builder's reasoning.

Known failure: isolation of context is not isolation of model. Evaluators that are all the same model and the same
persona are still correlated. Vary them where it matters.

Origin: System 3 Company's pattern language ("artifact-before-account").
